# Web Modifier 功能演进规格说明书

## 问题陈述

当前 Web Modifier 采用简单的三栏布局（模板列表 + 单 iframe 编辑器 + 属性面板），仅支持模板级别选择和单页面编辑。用户需要将其演进为一个更强大的 IDE 式编辑器，具备多文件管理、页面间跳转、历史记录、导出打包以及从零搭建页面的能力。

## 用户与目标

**用户**：需要可视化编辑 HTML 模板的开发者/设计师，以及希望通过拖拽组件从零搭建网页的非技术用户。

**目标**：
1. 提供 VS Code 风格的多文件编辑工作区（活动栏 + 文件树 + 标签页 + 编辑器）
2. 支持模板内页面间无缝跳转（文件树点击 + 页面内链接）
3. 提供完整的编辑历史（撤销/重做）和导航历史（前进/后退）
4. 导出支持自定义名称/位置，并自动打包为 ZIP
5. 提供空白模板构建器，通过拖拽组件搭建页面
6. 扩展可编辑组件类型（媒体、布局、表单）

## 非目标

- 不实现代码编辑器视图（保持可视化编辑定位）
- 不实现多用户协作
- 不集成版本控制（Git）
- 不替换富文本编辑为完整所见即所得编辑器
- 不改变 `@wt:edit` 标记规范的向后兼容性

## 功能需求

### FR1：VS Code 风格 IDE 布局

- 左侧增加**活动栏**（Activity Bar），含资源管理器、构建器、历史等图标按钮
- **资源管理器**面板以树形结构展示当前模板的所有文件（HTML/CSS/JS/图片等）
- 顶部增加**标签页栏**（Tab Bar），显示已打开的页面，支持切换/关闭
- 编辑器区域居中，右侧保留属性面板
- 活动栏可折叠/展开资源管理器面板

### FR2：多文件导航

- 点击资源管理器中的 HTML 文件 → 在编辑器中打开该页面并解析可编辑区段
- 在 iframe 中点击页面内链接（`<a href="about.html">`）→ 自动切换到目标页面
- 标签页切换不丢失各页面的编辑状态
- 关闭标签页时若有未保存更改给出提示（编辑状态跟踪）

### FR3：历史记录

- **导航历史**：前进/后退按钮，记录页面跳转轨迹
- **编辑历史**：撤销（Ctrl+Z）/ 重做（Ctrl+Y），记录每个可编辑区段的值变更
- **历史面板**：可查看编辑历史列表，点击任意历史节点可回滚到该状态
- 编辑记录包含「旧值 + 新值」完整快照，支持空字符串回滚

### FR4：导出自动打包

- 保留现有自定义导出名称 + 目录选择功能
- 导出文件夹生成后，**自动打包为 ZIP 压缩包**（与导出文件夹同名 `.zip`）
- 导出对话框增加「打包为 ZIP」复选框（默认勾选）
- 打包完成后提示 ZIP 文件路径
- ZIP 包含完整导出内容（HTML + 资产），不含任何 `@wt:*` 标记

### FR5：空白模板构建器

- 提供「新建空白模板」入口，创建一个空白 HTML 画布
- 左侧活动栏切换到**构建器**视图，展示可拖拽的组件面板
- 组件面板分类：基础（文本/标题/图片/链接）、媒体（视频/音频）、布局（按钮/卡片/网格/分割线/间距）、表单（输入框/文本域/下拉/复选框）
- 拖拽组件到画布 → 生成对应 HTML 结构并自动注入 `@wt:edit` 标记，成为可编辑区段
- 画布实时预览，属性面板可编辑已放置组件的属性
- 构建的页面可保存为模板，进入常规编辑流程

### FR6：扩展可编辑组件类型

在现有 7 种类型（text/richtext/image/link/color/list/html）基础上新增：

- **媒体类**：`video`（src/poster/controls）、`audio`（src/controls）
- **布局类**：`button`（文本/链接）、`divider`（样式/颜色）、`spacer`（高度）
- **表单类**：`input`（type/placeholder/value）、`textarea`、`select`（选项列表）、`checkbox`（选中状态/标签）

每种新类型在属性面板中有对应编辑控件，导出时正确写回 HTML。

## 非功能需求

- **性能**：拖拽交互流畅（60fps），页面切换无明显卡顿
- **兼容性**：现有模板和标记规范完全向后兼容
- **动画**：所有面板切换、标签页、拖拽反馈使用 framer-motion 平滑过渡
- **稳定性**：撤销/重做在边界情况（空值、连续操作）下行为正确

## 约束与假设

- 必须继续使用 `wt-template://` 自定义协议加载模板
- 导出必须保留原 HTML 格式（不使用 cheerio 序列化）
- 标记规范 `@wt:edit` / `data-wt-edit` 不变，新类型复用同一套机制
- ZIP 打包使用 Node.js 内置能力或轻量库（避免引入重量级依赖）
- 空白构建器生成的 HTML 必须符合现有解析器可识别的标记格式

## 验收标准

### AC1（rule）：VS Code 布局完整呈现
- 应用启动后可见左侧活动栏、资源管理器文件树、顶部标签页栏、中央编辑器、右侧属性面板
- 活动栏点击可切换资源管理器/构建器/历史面板
- 资源管理器以树形展示模板内所有文件

### AC2（rule）：文件树与链接双向导航
- 点击文件树中任意 HTML 文件 → 编辑器加载该页面，可编辑区段被识别
- 在 iframe 中点击指向同模板内其他页面的链接 → 编辑器自动切换到目标页面
- 标签页显示所有已打开页面，点击可切换，关闭按钮可关闭

### AC3（rule）：撤销/重做功能正确
- 修改任意可编辑区段值后，Ctrl+Z 恢复到修改前的值
- 撤销后 Ctrl+Y 可重做恢复
- 连续多次修改后逐步撤销可依次回退，空字符串值也能正确回滚

### AC4（rule）：导航历史前进后退
- 在多个页面间跳转后，后退按钮可回到上一页面，前进按钮可再前进
- 导航历史不丢失各页面的编辑状态

### AC5（rule）：导出自动打包 ZIP
- 导出时勾选「打包为 ZIP」→ 导出文件夹生成后，同目录下生成同名 `.zip`
- ZIP 解压后内容与导出文件夹一致，且不含任何 `@wt:*` / `data-wt-*` 标记
- 不勾选时仅生成文件夹，不生成 ZIP

### AC6（rule）：空白构建器拖拽生成页面
- 新建空白模板后，从组件面板拖拽一个组件到画布 → 画布出现对应 HTML 元素
- 拖拽的元素自动带有 `@wt:edit` 标记，可被属性面板编辑
- 保存后该模板出现在模板列表中，可正常打开编辑和导出

### AC7（rule）：新增组件类型可编辑可导出
- video/audio/button/divider/spacer/input/textarea/select/checkbox 类型在属性面板有对应编辑控件
- 修改这些组件的属性后，导出的 HTML 中对应属性值被正确更新，标记被剥离

### AC8（rubric）：交互流畅度
- 维度：拖拽与面板切换的动画流畅度
- 评分：0-2，0=卡顿/无动画，1=基本流畅但有跳变，2=丝滑连贯
- 通过阈值：≥ 1
- 证据来源：实际操作观察

### AC9（rubric）：布局还原度
- 维度：整体布局与 VS Code 风格的接近程度
- 评分：0-2，0=差异大，1=核心要素具备，2=高度还原
- 通过阈值：≥ 1
- 证据来源：界面截图对比
